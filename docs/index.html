Lasso Simulation Study

Anurag Nepal

GitHub repo · Full report (PDF) · Simulation results (CSV)

Background

I wanted to know how well lasso actually recovers the true variables when the dimension grows. Theory says lasso can select correctly under the right conditions, but I wanted to see the trade-offs myself: how the choice between the minimum-lambda and 1se-lambda tuning rules plays out across sample sizes, dimensions, signal strengths, and predictor correlations.

Setup

No real data here. I simulated it: 5 true signals out of p predictors, with AR(1) correlation structure between predictors, Gaussian noise, and a separate 500-row test set per replication. The full grid is sample size n in {50, 100, 200}, dimension p in {200, 400, 600}, signal strength A in {0.5, 1.0, 1.5}, and predictor correlation rho in {0, 0.5, 0.8}, with 100 replications per setting run in parallel. Each setting uses its own seed so the whole study is reproducible.

Method

The simulation

For each setting I draw training and test data from a multivariate normal with Toeplitz covariance, set the first five coefficients to alternating +A/-A, and fit lasso via cv.glmnet with 10-fold CV. I record both the lambda.min and lambda.1se solutions. Each fit is scored on selection metrics, sensitivity, false positive rate, precision, exact recovery of the true support, and estimation error, plus test MSE on the held-out 500 rows. Results are averaged over the 100 replications and written to lasso_simulation_results.csv, which is in this repo.

library(glmnet)
library(MASS)
library(dplyr)
library(tidyr)
library(foreach)
library(doParallel)

# Selection metrics for one fitted coefficient vector.
# Compares the estimated support {j : beta_hat[j] != 0} against the true
# support. Returns c(sensitivity, fpr, precision, exact_recovery, est_error).
calculate_metrics <- function(beta_true, beta_hat) {
  p <- length(beta_true)
  true_support <- which(beta_true != 0)
  est_support <- which(beta_hat != 0)
  tp <- length(intersect(true_support, est_support))
  fp <- length(setdiff(est_support, true_support))
  sensitivity <- tp / length(true_support)
  fpr <- fp / (p - length(true_support))
  precision <- if (length(est_support) == 0) 0 else tp / length(est_support)
  exact_recovery <- as.numeric(setequal(true_support, est_support))
  est_error <- sqrt(sum((beta_hat - beta_true)^2))
  c(sensitivity, fpr, precision, exact_recovery, est_error)
}

n_vals <- c(50, 100, 200)
p_vals <- c(200, 400, 600)
A_vals <- c(0.5, 1.0, 1.5)
rho_vals <- c(0, 0.5, 0.8)
n_reps <- 100
test_n <- 500 

settings <- expand.grid(n = n_vals, p = p_vals, A = A_vals, rho = rho_vals)
total_settings <- nrow(settings)

# Setup Parallel
num_cores <- detectCores() - 1 
cl <- makeCluster(num_cores)
registerDoParallel(cl)

cat("Starting parallel simulation on", num_cores, "cores...\n")

#parallel computing for faster processing
final_results <- foreach(i = 1:total_settings, 
                         .packages = c("glmnet", "MASS"), 
                         .combine = rbind) %dopar% {
  #set a single seed for each run so that the results are reproducable
  set.seed(748 + i) 
  
  n <- settings$n[i]
  p <- settings$p[i]
  A <- settings$A[i]
  rho <- settings$rho[i]
  
  beta_true <- rep(0, p)
  beta_true[1:5] <- c(A, -A, A, -A, A)
  
  first_row <- rho^(0:(p-1))
  Sigma <- toeplitz(first_row)
  
  metrics_min <- matrix(0, nrow = n_reps, ncol = 6) 
  metrics_1se <- matrix(0, nrow = n_reps, ncol = 6)
  
  for (rep in 1:n_reps) {
    X_train <- mvrnorm(n, mu = rep(0, p), Sigma = Sigma)
    eps_train <- rnorm(n, mean = 0, sd = 1)
    Y_train <- X_train %*% beta_true + eps_train
    
    X_test <- mvrnorm(test_n, mu = rep(0, p), Sigma = Sigma)
    eps_test <- rnorm(test_n, mean = 0, sd = 1)
    Y_test <- X_test %*% beta_true + eps_test
    
    cv_fit <- cv.glmnet(X_train, Y_train, alpha = 1, intercept = TRUE, standardize = TRUE)
    
    beta_hat_min <- as.vector(coef(cv_fit, s = "lambda.min"))[-1]
    beta_hat_1se <- as.vector(coef(cv_fit, s = "lambda.1se"))[-1]
    
    pred_min <- predict(cv_fit, newx = X_test, s = "lambda.min")
    pred_1se <- predict(cv_fit, newx = X_test, s = "lambda.1se")
    
    mse_min <- mean((Y_test - pred_min)^2)
    mse_1se <- mean((Y_test - pred_1se)^2)
    
    eval_min <- calculate_metrics(beta_true, beta_hat_min)
    eval_1se <- calculate_metrics(beta_true, beta_hat_1se)
    
    metrics_min[rep, ] <- c(eval_min, mse_min)
    metrics_1se[rep, ] <- c(eval_1se, mse_1se)
  }
  
  avg_min <- colMeans(metrics_min)
  avg_1se <- colMeans(metrics_1se)
  
  data.frame(
    n = n, p = p, A = A, rho = rho,
    min_sensitivity = avg_min[1], min_fpr = avg_min[2], min_precision = avg_min[3],
    min_exact_recovery = avg_min[4], min_est_error = avg_min[5], min_mse = avg_min[6],
    lse_sensitivity = avg_1se[1], lse_fpr = avg_1se[2], lse_precision = avg_1se[3],
    lse_exact_recovery = avg_1se[4], lse_est_error = avg_1se[5], lse_mse = avg_1se[6]
  )
}

stopCluster(cl)
write.csv(final_results, "lasso_simulation_results.csv", row.names = FALSE)

Results

The five saved plots show the headline patterns. Sensitivity climbs with sample size for both tuning rules. Exact recovery collapses as predictor correlation rises, which is the setting where lasso’s selection guarantees break down. Precision improves with signal strength. And the false positive rate needs care in high dimensions: the rate can look artificially low simply because the denominator of noise variables keeps growing, so the metric choice matters as much as the tuning choice.

From simulation to real data: does the 1se rule still win on stability?

The simulation study compares the minimum-lambda and 1se-lambda tuning rules across sample sizes, dimensions, and correlations, and finds the 1se rule more conservative. I asked the same question on real data: the diabetes progression set (442 patients, 10 standardized baseline predictors), with selection stability measured directly by bootstrapping 200 times and recording which predictors each rule keeps.

The 1se rule keeps exactly the four predictors both rules agree are rock-solid (selected in at least 94% of bootstraps under either rule). Everything the min rule adds on top, sex, s1, s6, age, is marginal: kept often by min, dropped almost always by 1se. That is the same conservatism the simulation found, now visible on real data: the 1se rule trades those borderline predictors for a smaller set that does not wobble across resamples.

Limits. One real dataset, ten predictors, so this is an illustration, not a general proof. Bootstrap selection frequencies describe this data, not the true model. The simulation study remains the systematic evidence; this is the reality check.

Takeaway

Lasso recovers the true variables reliably when signals are strong and predictors are independent, but exact recovery breaks down under high correlation, and that is the realistic case for most applied data. The 1se rule buys stability at the cost of sensitivity, and in high dimensions the raw false positive rate flatters every method because the denominator keeps growing. The practical lesson is to pick the metric before picking the tuning rule.
